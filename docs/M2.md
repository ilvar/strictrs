# M2 mechanical fix loop

M2 adds a bounded `check → patch → re-check` loop on top of the M0/M1 diagnostic contract.

## Safety model

The fixer applies only replacements emitted by rustc or Clippy with `suggestion_applicability` set to `MachineApplicable`. It never synthesizes replacement text.

The public JSON contract remains unchanged. Each fix retains its source file and rustc byte range internally with `#[serde(skip)]` metadata so edits do not depend on display columns.

## Patch pass

For each iteration, the fixer:

1. groups applicable edits by normalized project-relative file;
2. rejects paths outside the project root;
3. removes exact duplicates;
4. keeps the first deterministic candidate when alternatives overlap;
5. validates ranges and UTF-8 boundaries;
6. applies edits from the highest byte offset to the lowest;
7. writes changed files;
8. runs the complete M1 checker again.

Back-to-front application prevents earlier replacements from invalidating offsets for edits nearer the end of the same file.

## Termination

The loop stops when any of these conditions is reached:

- the report is clean;
- no applicable edit remains;
- a patch pass changes no source text;
- the new report is identical to the previous report;
- the configured iteration cap is reached.

The default cap is 10 iterations. `run_fix_with_limit` exposes a lower or higher cap for callers and tests.

## CLI

```bash
strictrs check path/to/project
strictrs fix path/to/project
```

Both commands print the ordinary final diagnostic report. The fix command does not introduce a second output schema.

## Tests

M2 coverage includes:

- two edits in one file, proving back-to-front application;
- overlapping alternatives, proving deterministic conflict handling;
- an end-to-end repair of two wildcard imports using Clippy's machine-applicable replacements;
- a partial repair followed by termination at an unfixable panic-API violation;
- a zero-iteration cap that leaves sources untouched.
